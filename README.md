# Android Desk

Работающее Windows x64 приложение на C# / WinUI 3 для управления Android через готовый scrcpy. Интерфейс на русском, Mica, системная светлая/тёмная тема. Используется локальный комплект `scrcpy/` (проверено с 5.0.1).

## Запуск

Откройте `dist/AndroidDesk/AndroidDesk.exe` или дважды нажмите `Android Desk.cmd` в корне проекта. Сборка переносимая: .NET и Windows App SDK включены, установка MSIX и права администратора не нужны. При переносе скопируйте **всю** папку `dist/AndroidDesk`, а не один EXE. Нужна Windows 10 2004+ x64; основной интерфейс рассчитан на Windows 11 и окно примерно 1180×860 физических пикселей или больше.

1. Включите на Android режим разработчика и отладку по USB.
2. Подключите телефон, разблокируйте его и разрешите отладку с этого компьютера.
3. Запустите Android Desk: приложение проверяет ADB каждые две секунды и автоматически подключается к первому доступному устройству. При нескольких устройствах отключите текущую сессию, выберите телефон в списке и нажмите «Подключить».
4. Щёлкните по изображению телефона для ввода мышью и клавиатурой. Справа доступны «Назад», «Домой», недавние приложения, громкость, питание и скриншот. На некоторых realme/Xiaomi для инъекции ввода требуется дополнительное разрешение отладки в настройках производителя — приложение его само не меняет.

Устройства, уже подключённые к ADB по Wi-Fi, тоже обнаруживаются. Само сопряжение Wireless Debugging в эту первую версию не входит. Для наименьшей задержки используйте USB; качество Wi-Fi зависит от сети. При необходимости выключите автоподключение и примените настройки.

## Экран и ввод

Видео декодируется и отображается самим scrcpy. Его SDL-окно превращается в дочерний HWND WinUI-окна через `SetParent` и размещается над выделенной областью XAML. Пропорции сохраняет scrcpy. Размер и DPI пересчитываются при изменении области и XamlRoot. Перехват кадров, собственный видеодекодер и пересылка мыши через ADB не используются.

Это практическое встраивание внешнего окна, а не официальный компонент WinUI/scrcpy. SDL, драйверы, смена DPI и фокус между процессами могут влиять на поведение. Нативное окно находится поверх XAML: поверх видео нельзя надёжно размещать XAML-диалоги и всплывающие панели. Поэтому все элементы управления вынесены справа и вниз. Если встраивание не работает на другом ПК, включите «Отдельное окно scrcpy» и нажмите «Применить настройки». Если автоматическое подключение не удалось, этот переключатель остаётся доступен для следующей попытки.

В отдельном режиме доступны обычные горячие клавиши scrcpy, включая Alt+F. Во встроенном режиме не переключайте scrcpy в полный экран: это может нарушить привязку дочернего окна. Alt+H отправляет «Домой», Alt+B — «Назад». По умолчанию используется стандартный SDK-ввод scrcpy; прямой ввод произвольных Unicode-символов ограничен самим scrcpy/Android. Для русского текста можно использовать синхронизацию буфера обмена scrcpy и вставку Ctrl+V. Режим UHID в интерфейсе этой версии не предусмотрен.

## Качество и запись

- Длинная сторона: 1280 / 1920 / 2560 px или оригинал.
- Ограничение кадров: 30 / 60 / 90 / 120 FPS. Это верхний предел, а не обещанная частота: scrcpy передаёт кадры при изменении изображения.
- Битрейт: 1–64 Мбит/с. По умолчанию 1920 px, до 60 FPS, 8 Мбит/с, H.264, без дополнительного видеобуфера. Звук отключён.
- «Применить настройки» сохраняет их и перезапускает текущую трансляцию.
- Кнопка записи создаёт MKV в системной папке `Видео/AndroidDesk`. Поскольку готовый scrcpy принимает `--record` при запуске, начало и остановка записи коротко перезапускают сессию. Приложение использует один поток scrcpy, без второго энкодера на телефоне. Видео пишется без звука. Статичный экран может давать очень мало кадров и длительность файла меньше времени таймера.
- Остановка посылает `WM_CLOSE` SDL-окну и ждёт до 8 секунд, чтобы scrcpy дописал контейнер. Только при зависании процесс принудительно завершается с сообщением о возможном повреждении записи. При обычном закрытии приложения запись также финализируется.
- PNG-скриншоты сохраняются в системную папку `Изображения/AndroidDesk` в исходном разрешении через бинарный `adb exec-out screencap -p`.

Во время записи настройки качества заблокированы. При ошибке или закрытии scrcpy приложение показывает статус; ручное повторное подключение доступно кнопкой. Неудачный автоматический запуск не повторяется бесконечно: новую попытку можно сделать вручную или после отключения/подключения устройства.

Настройки и журнал: `%LOCALAPPDATA%/AndroidDesk/settings.json` и `app.log`. Кнопка «Журнал» открывает эту папку. Журнал содержит локальные диагностические сообщения scrcpy и идентификаторы устройств. Приложение не отправляет его в сеть и не завершает общий ADB-сервер при выходе.

## Сборка из исходников

Требуется .NET SDK 8+ x64, Windows SDK и доступ к NuGet при первом восстановлении. В Visual Studio откройте `AndroidDesk.sln` с поддержкой разработки WinUI/C#.

```powershell
# Debug
.\build.ps1

# Переносимая Release-сборка
.\build.ps1 -Publish

# Запуск Release (собирает, если её ещё нет)
.\run.ps1
```

Если локальная политика запрещает PowerShell-скрипты, выполните команды непосредственно:

```powershell
dotnet publish .\AndroidDesk\AndroidDesk.csproj -c Release -p:Platform=x64 -o .\dist\AndroidDesk
& '.\dist\AndroidDesk\AndroidDesk.exe'
```

Исходники: `MainWindow.xaml` — интерфейс; `MainWindow.xaml.cs` — состояние UI, подключение и жизненный цикл; `Services.cs` — ADB, scrcpy и настройки; `Native.cs` — Win32-встраивание. Все внешние аргументы передаются через `ProcessStartInfo.ArgumentList`, без командной оболочки. Полный комплект `scrcpy/` автоматически копируется при сборке и публикации. Лицензии стороннего комплекта остаются в `scrcpy/LICENSE.txt`; для распространения учитывайте условия всех включённых компонентов.

Проверки текущей сборки описаны в `VERIFICATION.md`.
