# Android Desk

Windows x64 приложение на C# / WinUI 3 для управления Android через локальный комплект scrcpy 5.0.1.

## Запуск

Дважды нажмите `Android Desk.cmd` или откройте `dist/AndroidDesk/AndroidDesk.exe`. При переносе скопируйте **всю** папку `dist/AndroidDesk`. .NET и Windows App SDK включены в сборку; MSIX и права администратора не нужны. Требуется Windows 10 2004+ x64, интерфейс рассчитан на Windows 11.

Включите USB-отладку, подключите телефон и разрешите отладку с компьютера. Для подключения по сети откройте «Устройства → Wi-Fi». Приложение проверяет список устройств каждые две секунды.

## Главное окно

Экран занимает всю рабочую высоту окна, без шапки, нижней строки и постоянной панели настроек. При первом подключении ширина окна подстраивается под пропорции телефона и панель быстрых действий; высота — под рабочую область монитора, без перекрытия панели задач. Пропорции сохраняются без обрезания изображения. Окно можно менять вручную; кнопка подгонки внизу панели меняет только ширину под экран телефона, сохраняя текущую высоту и положение окна. Расчёт учитывает реальное соотношение сторон видеопотока, масштаб DPI, системную рамку и панель кнопок.

Справа находится панель шириной 44 логических пикселя с кнопками 34×34. Кнопка **⋯** расположена самой первой сверху; снизу оставлена только подгонка окна:

- **⋯**: отдельное окно настроек.
- Устройства: отдельное окно выбора устройства с моделью, типом соединения и серийным номером; список обновляется автоматически. Окно увеличено по высоте, прокручивается только список, кнопка «Подключить» закреплена снизу.
- Быстрые команды ADB: отдельное окно библиотеки и редактора.
- Подключить / отключить текущий телефон.
- Назад, домой, недавние приложения, громче, тише, питание.
- PNG-скриншот.
- Начать / остановить запись; во время записи появляется небольшой таймер.
- Подогнать окно по телефону.

При переключении телефона текущая запись корректно завершается. При нескольких устройствах выберите нужное в окне «Выбор устройства» и нажмите «Подключить».

Сообщение о сохранении скриншота или видео показывается отдельным небольшим уведомлением с радиусом углов около 6 px без обводки сверху изображения и исчезает через 3 секунды; ошибки — через 7 секунд. Маленькая кнопка открытия файла справа открывает Проводник; имя файла доступно в её подсказке. Постоянного журнала и строки состояния в интерфейсе нет.

## Настройки и запись

В окне ⋯ доступны:

- Длинная сторона изображения: **720, 960, 1280, 1600, 1920, 2560 px** или оригинальное разрешение. Это ограничение длинной стороны, а не строгое обозначение 720p/1080p.
- До 30 / 60 / 90 / 120 FPS. Фактическая частота зависит от устройства и изменений изображения.
- Битрейт 1–64 Мбит/с.
- Формат записи **MP4** или MKV; видео H.264, звук AAC.
- Звук в записи, автоподключение и отдельное окно scrcpy.
- Физическая клавиатура UHID (по умолчанию) или совместимый ввод SDK.
- Общий текстовый буфер между ПК и выбранным устройством (по умолчанию включён).
- Кнопка открытия папки видеозаписей.

По умолчанию новые настройки записи — **MP4 со звуком**. Обычная трансляция идёт без звука; во время записи включается захват аудиовыхода телефона, воспроизведение на ПК отключено. Микрофон не записывается. Захват звука scrcpy требует Android 11+; на Android 11 телефон должен быть разблокирован. Захват защищённого контента может ограничиваться Android или приложением. Если AAC/аудиозахват не работает, запись не продолжается молча без звука: обычная трансляция восстанавливается, выводится ошибка; звук можно выключить в настройках.

Начало и остановка записи коротко перезапускают scrcpy: готовая программа принимает `--record` при запуске. «Применить» также перезапускает текущую трансляцию. При переключении записи и применении настроек старый scrcpy продолжает показывать живое видео, пока новый готовит поток. Новое дочернее окно сначала прогревается вне видимой области, затем за старым окном в той же области, и только после подготовки показывается. Подмена видео отдельно масштабированным PNG не используется; размер главного окна при этом не меняется. На время перехода кратковременно работают два процесса scrcpy, после перехода старый штатно завершается и остаётся один. Если новый поток не удалось подготовить, прежняя трансляция и запись продолжают работать. PNG в памяти используется только для обычной ручной остановки, чтобы оставить изображение до следующего подключения. Во время записи изменять настройки нельзя. После переключения один процесс scrcpy отвечает за экран, ввод и запись. MKV/MP4 завершается через `WM_CLOSE` SDL-окну, приложение ждёт до 8 секунд. При зависании процесс принудительно закрывается с предупреждением о возможном повреждении записи. Обычное закрытие приложения также финализирует запись.

Видео: системная папка `Видео/AndroidDesk`. PNG в исходном разрешении: `Изображения/AndroidDesk`. Скриншот получается бинарным `adb exec-out screencap -p`. Статичный экран может передавать мало кадров; длительность файла и таймер иногда отличаются.

## Встраивание и ввод

Готовое SDL-окно scrcpy превращается в дочерний HWND через Win32 `SetParent`. Размер и DPI синхронизируются с выделенной областью WinUI. Собственный движок трансляции не используется. Щёлкните по экрану телефона для мыши и клавиатуры. Alt+H — домой, Alt+B — назад. По умолчанию включена физическая клавиатура UHID. Для русского набора один раз выберите русскую раскладку физической клавиатуры в Android; Alt+K открывает настройки раскладки. Windows и Android имеют отдельные раскладки. Если UHID не поддерживается устройством, выключите его в ⋯: останется совместимый SDK-ввод с ограничениями символов. Кириллица из буфера вставляется через Ctrl+V независимо от физической раскладки.

Во встроенном режиме приложение передаёт фокус дочернему HWND при щелчке по экрану. Если клавиатурное событие получает WinUI, оно перенаправляется окну SDL; глобального перехвата клавиатуры нет. Для начала печати щёлкните по полю на телефоне. После открытия настроек/выбора устройства щёлкните по экрану снова.

Общий **текстовый** буфер работает автоматически в обе стороны: телефон → ПК через клиент scrcpy, ПК → телефон через отдельный control-only канал штатного scrcpy-server 5.0.1. Он не запускает второй видеопоток и не вставляет текст в открытые поля сам. Файлы и изображения не синхронизируются. Канал использует локальный порт 127.0.0.1 и ADB-forward к выбранному устройству, закрывается при остановке сессии и выходе, а на переключении записи сохраняется. Тексты не пишутся в журнал. Максимальный размер UTF-8 текста — около 256 КБ. Синхронизацию можно выключить в ⋯; штатная вставка Ctrl+V scrcpy останется доступна.

Встраивание внешнего процесса зависит от SDL, драйверов и DPI. Если на другом ПК возникают проблемы, включите отдельное окно в настройках. Настройки, выбор устройства и уведомления сделаны отдельными окнами, чтобы их не перекрывало нативное видео. В отдельном режиме доступен Alt+F; во встроенном режиме полный экран scrcpy может нарушить его привязку.

На некоторых realme/Xiaomi управление требует дополнительного разрешения отладки производителя. Приложение не меняет настройки безопасности телефона. Для минимальной задержки используйте USB; дополнительных видеобуферов нет. Устойчивая частота и задержка зависят от телефона и сети.

## Сборка и проверка

Нужны .NET SDK 8+ x64, Windows SDK и доступ к NuGet при первом восстановлении. Для Visual Studio откройте `AndroidDesk.sln` с поддержкой разработки WinUI/C#.

```powershell
.\build.ps1                  # Debug
.\build.ps1 -Publish         # Переносимая Release в dist/AndroidDesk
.\run.ps1                    # Запуск Release
```

Без PowerShell-скриптов:

```powershell
dotnet publish .\AndroidDesk\AndroidDesk.csproj -c Release -p:Platform=x64 -o .\dist\AndroidDesk
& '.\dist\AndroidDesk\AndroidDesk.exe'
```

Закройте приложение перед пересборкой его выходной папки. Комплект `scrcpy/` включён в локальный Git и копируется при сборке. XBF/PRI WinUI явно копируются после Publish — проверено запуском именно из `dist`.

Интеграционная проверка захвата реального MP4/AAC, без имитации ADB или scrcpy:

```powershell
dotnet run --project .\AndroidDesk.Smoke -- DEVICE_SERIAL
dotnet run --project .\AndroidDesk.Smoke -- DEVICE_SERIAL --clipboard
```

Первая команда запускает отдельную четырёхсекундную сессию scrcpy на выбранном устройстве, сохраняет `Видео/AndroidDesk/Smoke_AAC_*.mp4` и корректно завершает её. Команда с `--clipboard` проверяет Unicode через настоящий буфер Android и восстанавливает исходный текст после теста. Список устройств: `scrcpy/adb.exe devices -l`. Для проверки нужны подключённый телефон и рабочий аудиозахват. Результаты ручных и интеграционных проверок — в `VERIFICATION.md`.

Кнопки Android используют отдельную последовательную очередь ADB, а сохранение PNG выполняется отдельно от управления сессией. Они не блокируют остальные кнопки панели. На время смены сессии недоступны только подключение и запись; настройки и выбор устройства можно открывать. Повторный щелчок по скриншоту, пока он сохраняется, не создаёт дубликат задания.

Настройки: `%LOCALAPPDATA%/AndroidDesk/settings.json`. Диагностика: `app.log` в той же папке; журнал сохраняется локально и может содержать идентификаторы устройств. Приложение не завершает общий ADB-сервер. Лицензии стороннего комплекта — в `scrcpy/LICENSE.txt`.

Исходники: `MainWindow.xaml` — компактный интерфейс; `MainWindow.xaml.cs` — состояние и жизненный цикл; `ToolWindows.cs` — настройки, выбор телефона, уведомления; `Services.cs` — ADB/scrcpy и настройки; `Native.cs` — Win32; `ClipboardBridge.cs` — control-only соединение для текстового буфера. Внешние аргументы передаются через `ProcessStartInfo.ArgumentList`, без командной оболочки.

## Подключение по Wi-Fi

Поддерживается беспроводная отладка Android 11+. Компьютер и телефон должны находиться в одной сети.

1. На телефоне включите «Для разработчиков → Беспроводная отладка».
2. В приложении откройте «Устройства → Wi-Fi». Адреса ищутся через ADB mDNS; если поиск ничего не нашёл, введите IP:порт вручную.
3. При первом подключении раскройте «Первое подключение · сопряжение». На телефоне откройте «Сопряжение с помощью кода» и перенесите оттуда IP:порт и шестизначный код. Нажмите «Выполнить сопряжение».
4. В поле «Адрес подключения» укажите IP:порт с главного экрана беспроводной отладки. **Порт подключения отличается от порта сопряжения.** Нажмите «Добавить устройство».
5. Телефон появится в общем списке с пометкой Wi-Fi. Он будет выбран; нажмите закреплённую кнопку «Подключить», чтобы переключить трансляцию на него. USB-кабель больше не нужен.

После сопряжения обычно достаточно повторного добавления по актуальному адресу; ключи хранит штатный ADB. Приложение не сохраняет и не журналирует код сопряжения. При смене сети или перезапуске отладки порт может измениться — обновите поиск или возьмите актуальный адрес с телефона. При блокировке mDNS сетью работает ручной ввод. Адрес уже настроенного ADB TCP/IP (например IP:5555) тоже можно ввести вручную; автоматическое включение этого режима по USB не выполняется.

Основа: [официальная инструкция Android Wireless Debugging](https://developer.android.com/tools/adb#wireless-android11-command-line).

## Быстрые команды ADB

Кнопка терминала на правой панели открывает отдельное окно. Слева — список с поиском по названию и тексту; закреплённые команды идут первыми. Справа — название, команда, флажок закрепления, кнопки сохранения/удаления/выполнения и текстовый результат. Для добавления ещё одной команды нажмите «+ Новая команда». Сохранение доступно и без подключённого телефона.

Например, название «Модель телефона», команда `adb shell getprop ro.product.model`. Префикс `adb` / `adb.exe` необязателен. Телефон берётся из текущего выбора; `-s`, `-d`, `-e` перед командой не нужны. Для файловых путей с пробелами используйте двойные кавычки, например `adb install "C:\Apps\my app.apk"`. Текст после `shell` передаётся оболочке Android с исходными кавычками и переносами строк. Windows cmd.exe / PowerShell не запускаются, объединение нескольких локальных ADB-вызовов через `&&` не поддерживается.

Чтобы добавить команду на боковую панель, включите «Закрепить на панели быстрого доступа» и нажмите «Сохранить». Кнопка с первыми двумя буквами названия появится сразу; полное название и команда видны в подсказке. Если закреплений много, область прокручивается колёсиком. Подгонка окна остаётся снизу.

Закреплённая команда выполняется одним нажатием, без открытия редактора. На время выполнения блокируется только её собственная кнопка; другие команды и управление телефоном остаются доступны. Короткое уведомление сообщает о завершении; последний результат запуска с панели можно посмотреть в окне команд. Телефон фиксируется в момент запуска, переключение устройства не перенаправляет уже запущенный вызов.

В окне есть «Остановить», автоматический лимит выполнения — 60 секунд. Останавливается клиент ADB; удалённый процесс на Android может продолжить работу. Это запуск отдельных команд с текстовым выводом, а не интерактивный терминал; непрерывный `logcat` прервётся по лимиту. stdout и stderr ограничены 64 тысячами символов каждый, остальной поток читается без сохранения, чтобы не заполнять память. Код завершения показывается рядом с результатом.

Библиотека хранится локально в `%LOCALAPPDATA%\AndroidDesk\commands.json`, отдельно от настроек и Git. Изменения записываются через временный файл с заменой. Вывод команд не сохраняется в журнал или на диск автоматически.
