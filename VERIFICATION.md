Среда: Windows 11 x64, .NET SDK 10.0.301, проект .NET 8 / Windows App SDK 1.8.260921001, scrcpy 5.0.1, реальный realme RMX5070 с Android 15 по USB.

## Сборка

- Debug: успешная сборка, 0 ошибок, 0 предупреждений.
- Release: успешная публикация в `dist/AndroidDesk` с .NET, Windows App SDK, XBF/PRI приложения и локальным комплектом scrcpy.
- Реальное главное окно проверено после запуска собранного EXE: узкая панель, изображение на всю высоту рабочей области, без прежней шапки, нижней строки, журнала и постоянных настроек.

## Проверки на реальном устройстве

- Автоподключение к USB-устройству; живое изображение встроено в WinUI. Direct3D 11 / D3D11VA подтверждены журналом.
- Главное окно подстроено под пропорции телефона: экран без внутренних отступов, справа панель 44 логических px, кнопки 34×34.
- Кнопкой ⋯ открыто отдельное окно настроек; проверены поля разрешения, FPS, битрейта, MP4/MKV, звука, отдельного окна и автоподключения.
- В списке разрешений проверены 720, 960, 1280, 1600, 1920 и 2560; оригинал также предусмотрен. Через интерфейс выбрано и применено 960. Настройка сохранена в JSON, новая текстура scrcpy — 432×960.
- С панели запущена и остановлена запись MP4 с включённым звуком. scrcpy штатно сообщил `Recording complete`. В реальном файле обнаружены H.264 и AAC, видеокадры декодированы, декодировано 975872 аудиосэмпла. Обычная трансляция восстановлена после остановки записи.
- Отдельная интеграционная проверка `AndroidDesk.Smoke` использовала реальные ADB и scrcpy: 720 px / 30 FPS / 2 Мбит/с, четырёхсекундный MP4. PyAV подтвердил H.264-видео и AAC-аудио: 13 кадров видео, 189 аудиокадров / 193536 аудиосэмплов. Тест оставлен в исходниках для повторного запуска с серийным номером устройства.
- PNG-скриншот сделан кнопкой на панели. Уведомление «Скриншот сохранён» с именем файла и кнопкой «Показать файл» появилось поверх видео отдельным окном; через несколько секунд исчезло. Постоянной нижней строки нет.
- Кнопка телефона открыла отдельный выбор устройства с моделью, USB и серийным номером; текущее устройство выделено.
- Штатное закрытие главного окна закрыло окно выбора и принадлежащий приложению процесс scrcpy. Общий ADB-сервер не завершался.

В этой проверке не менялись громкость и блокировка телефона. Одновременно подключённого второго телефона не было: выбор проверен с одним реальным устройством. Сценарий ошибки аудио на старом Android, длительная запись, несколько мониторов/DPI и 90/120 FPS отдельно не проверялись. Сквозная задержка не измерялась. AAC-дорожка и её декодирование подтверждены; независимая проверка слышимости конкретного приложения не проводилась.

Для декодирования использовался PyAV из временной папки компьютера, он не входит в приложение. MP4/AAC реализован флагами штатного scrcpy (`--audio-codec=aac`, `--require-audio`, `--no-audio-playback`), без собственного движка.

История исходного интерфейса и его проверок сохранена в первом Git-коммите. Сборки, личные настройки, пользовательские записи и скриншоты в Git не включены.

- Кнопки Android работают в отдельной очереди, скриншоты — отдельно от сессии. Во время сохранения PNG все остальные действия оставались доступны; во время переключения записи доступными оставались Android-команды, настройки и выбор устройства. Повторный запуск смены сессии блокируется только для кнопок записи и подключения.
- Начало и остановка реальной MP4-записи проверены с удержанием PNG-кадра в памяти. Во время остановленного scrcpy в дереве интерфейса присутствовал FrozenFrame, изображение сохранялось без чёрного экрана/заглушки. Новый HWND размещается вне видимой области до появления видеотекстуры. Краткий промежуток отсутствия видео маскируется статичным кадром, не новым движком трансляции.
- Последний тестовый MP4 штатно завершён: декодированы 1155 видеокадров и 1904640 аудиосэмплов, H.264/AAC.
- Финальная Release-публикация завершилась успешно. Запущен EXE из dist; тестовый Debug-экземпляр закрыт, остались только Release и принадлежащий ему scrcpy.

Отдельно не проверялись физическое внезапное отключение кабеля и отказ получения PNG перед остановкой. Если ADB уже недоступен, новый стоп-кадр получить нельзя; используется ранее сохранённый кадр, если он есть. Непрерывный захват кадров в фоне не запускается.

## Дополнение: переход между живыми потоками и подгонка только ширины

- Уведомление получило небольшой радиус 6 px. Удалены стили системной рамки, отключена отрисовка non-client DWM; собственная область окна скруглена и подрезана на 1 px. При fallback цвет рамки чёрный. Проверено на реальном уведомлении о PNG и записи: белой обводки нет.
- Подмена видео PNG при старте/остановке записи и применении настроек убрана. Новая сессия запускается параллельно старой, ожидает видеотекстуру, размещается в той же области за старым HWND, затем выходит вперёд. Старый процесс закрывается только после этого. На переходе работают два scrcpy; после перехода остаётся один. При ошибке подготовки новый процесс закрывается, а предыдущая сессия сохраняется.
- В интерфейсе проверены начало и остановка MP4/AAC: старое изображение оставалось видимым во время запуска, FrozenFrame не появлялся, размеры окна сохранялись 392×801 в снимках интерфейса. Журнал подтвердил `live renderer handed over without PNG replacement` на обоих переходах и штатное `Recording complete`. После каждого перехода проверено, что остаётся один процесс scrcpy.
- Кнопка подгонки проверена после ручного изменения высоты: снимок до — 469×801, после — 392×801. Высота не изменилась. В native-координатах журнал зафиксировал сохранение высоты 808 px; отличие снимков связано с невидимой системной рамкой. Прежние боковые поля исчезли после подгонки.
- Соотношение сторон берётся из фактической видеотекстуры scrcpy; размеры non-client части берутся из Win32, ширина панели масштабируется по DPI. Кнопка не разворачивает окно на рабочую высоту монитора.

Это заменяет прежний механизм удержания PNG при переключении записи. Кратковременный параллельный запуск проверен на RMX5070 / Android 15 по USB; устройства с ограничением нескольких видеокодеров отдельно не проверены. Ошибка запуска нового потока оставляет старый поток работающим.

- Реализован постоянный PC → Android текстовый буфер через неизменённый bundled scrcpy-server 5.0.1 без видео/аудио. Успешное соединение видно в журнале и ADB-forward; после штатного закрытия тестового Debug-экземпляра forward исчез. Android → PC оставлен штатному клиенту scrcpy.

Режим совместимости SDK и другие модели телефонов отдельно не проверялись. Общий буфер предназначен только для текста; нет передачи файлов/изображений и нет отправки текста в поля без действия пользователя.

- `dotnet run --project AndroidDesk.Smoke -- --commands 319e4099` прошёл: библиотека из 150 команд, сохранение/перезагрузка, изменение существующего ID, закрепление и удаление. Также проверены путь Windows с пробелами, неизменность кавычек Android shell, реальный текстовый вывод, stderr с кодом 7 и отмена клиента, выполняющего sleep.

- В профиле оставлен один пример «Модель телефона», читающий модель без изменения телефона. Тестовая библиотека из 150 записей создана во временном файле и удалена.
