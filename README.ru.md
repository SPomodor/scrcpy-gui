# scrcpy GUI

[English](README.md) · **Русский**

Компактное приложение для управления Android-телефоном с Windows на **C# / WinUI 3**, **ADB** и готовом **scrcpy**. Окно приложения называется **Android Desk**.

Экран телефона занимает всю высоту окна, справа — узкая панель быстрых действий. Настройки, выбор устройства и библиотека команд открываются в отдельных окнах.

## Возможности

- Встроенный экран телефона с управлением мышью и клавиатурой.
- Автоматическое обнаружение и выбор устройств по USB и Wi-Fi.
- Беспроводное сопряжение по коду на Android 11+ и подключение по IP:порту.
- Назад, домой, недавние приложения, громкость, питание и скриншоты.
- Запись MP4/MKV: видео H.264 и необязательный звук телефона AAC.
- Ограничение длинной стороны: 720, 960, 1280, 1600, 1920, 2560 пикселей или оригинал; настройка FPS и битрейта.
- Общий текстовый буфер в обе стороны.
- Сохранённые ADB-команды с поиском и закреплением на боковой панели.
- Русский и английский интерфейс, системный выбор языка и переключение без перезапуска.
- Подгонка ширины окна под телефон с сохранением текущей высоты.

## Требования

- Windows 10 версии 2004 или новее. Выберите x64, x86 или ARM64 под архитектуру **компьютера**, не телефона. Интерфейс рассчитан на Windows 11.
- Android-телефон с включённой отладкой и разрешённым подключением компьютера.
- Для записи звука и беспроводного сопряжения по коду нужен Android 11+.
- Для сборки: .NET SDK 8 или новее, Windows SDK и средства разработки WinUI. При первом восстановлении нужен доступ к NuGet. Рекомендуется Visual Studio со средствами разработки Windows-приложений.

В опубликованную сборку включены .NET и Windows App SDK. Отдельная установка среды выполнения, MSIX и права администратора не нужны.

## Скачать переносимую версию

Откройте [Releases](https://github.com/SPomodor/scrcpy-gui/releases), скачайте ZIP, распакуйте в отдельную папку и запустите `AndroidDesk.exe` внутри. Все файлы папки должны оставаться вместе. Установщика и единственного EXE нет.

| Окончание имени архива | Для какого компьютера |
| --- | --- |
| `windows-x64.zip` | 64-битная Windows на Intel/AMD; рекомендуется большинству пользователей |
| `windows-x86.zip` | 32-битная Windows; работает и на x64 |
| `windows-arm64.zip` | Windows на ARM; интерфейс и scrcpy ARM64, штатный ADB x86 через эмуляцию ОС |

ARM64 собирается кросс-компиляцией с проверкой состава пакета; на настоящем ARM64-компьютере пока не проверена. Контрольные суммы архивов — в `SHA256SUMS.txt` каждого релиза.

## Сборка и запуск

```powershell
git clone git@github.com:SPomodor/scrcpy-gui.git
cd scrcpy-gui
.\build.ps1 -Publish
.\run.ps1
```

Или без скриптов:

```powershell
dotnet publish .\AndroidDesk\AndroidDesk.csproj -c Release -p:Platform=x64 -o .\dist\AndroidDesk
& '.\dist\AndroidDesk\AndroidDesk.exe'
```

После сборки можно запускать `Android Desk.cmd`. Для переноса скопируйте **всю** папку `dist/AndroidDesk`. Перед повторной публикацией в ту же папку закройте приложение.

В репозитории находится предоставленный комплект **scrcpy 5.0.1 Windows x64** в папке `scrcpy/`. Он копируется при сборке. Для других архитектур и релизных архивов скрипт скачивает официальные комплекты 5.0.1 с проверкой закреплённых SHA-256; кеш находится в игнорируемой папке `artifacts/tools/`. Протокол общего буфера зависит от версии scrcpy-server, поэтому не заменяйте отдельные файлы версиями из другого комплекта.

[Windows workflow](.github/workflows/build.yml) собирает и проверяет ZIP для x64, x86 и ARM64. Сборки ветки main и PR попадают в артефакты Actions; теги версий после успеха всех трёх сборок создают постоянный GitHub Release.

```powershell
.\build.ps1 -Publish -Architecture x86       # dist/AndroidDesk-x86
.\build.ps1 -Publish -Architecture arm64     # dist/AndroidDesk-arm64
.\scripts\New-ReleasePackage.ps1 -Architecture x64 -Version 1.0.0
```

По умолчанию используется x64. Для других архитектур при первом запуске нужен интернет. При прямом вызове MSBuild для x86/ARM64 нужно передать `ScrcpyToolsDirectory` с подходящим комплектом; скрипт сборки делает это сам.

Для следующего релиза после коммита и отправки изменений:

```powershell
git tag -a v1.0.1 -m "Release v1.0.1"
git push origin v1.0.1
```

Workflow сам собирает три ZIP, проверяет контрольные суммы, формирует описание и добавляет архивы вместе с `SHA256SUMS.txt` в Releases. Теги вроде `v1.0.1-rc.1` создают предварительный релиз. Обычный push в main релиз не создаёт.

## Подключение телефона

### USB

Включите USB-отладку, подключите телефон и разрешите компьютер на экране телефона. Список обновляется каждые две секунды. Кнопкой «Выбор устройства» можно переключаться между телефонами и типами подключения.

### Wi-Fi

1. Подключите компьютер и телефон к одной сети.
2. На Android 11+ включите «Для разработчиков → Беспроводная отладка».
3. В приложении откройте «Выбор устройства → Wi-Fi».
4. Для первого подключения раскройте «Первое подключение · сопряжение». На телефоне выберите «Сопряжение с помощью кода» и перенесите адрес IP:порт и шестизначный код из этого окна.
5. Укажите адрес с главного экрана беспроводной отладки и нажмите «Добавить устройство». **Порты сопряжения и подключения отличаются.**
6. Выберите Wi-Fi-устройство в общем списке и нажмите «Подключить». После этого кабель можно отключить.

Адреса обнаруживаются через ADB mDNS; если поиск недоступен, введите адрес вручную. Порт может измениться после перезапуска отладки или смены сети. Поддерживаются и ранее настроенные адреса ADB TCP/IP вроде `IP:5555`; приложение не включает этот режим автоматически.

## Запись, ввод и буфер

Начало и остановка записи — на боковой панели. В «⋯ Настройки» выбираются MP4/MKV и запись звука телефона. Обычная трансляция идёт без звука; при записи звук телефона захватывается без воспроизведения на ПК. Микрофон не записывается. На Android 11 перед захватом звука разблокируйте телефон.

scrcpy получает параметры записи при запуске. Во время переключения записи или настроек старый поток остаётся видимым, пока новый готовится. На короткое время запускаются два процесса scrcpy; возможность перехода зависит от видеокодеров телефона. При ошибке нового потока прежняя сессия сохраняется. Дождитесь завершения записи перед отключением телефона.

Для печати щёлкните по экрану телефона. По умолчанию используется физическая клавиатура UHID; в настройках доступен совместимый SDK-ввод. Для русского набора выберите русскую **физическую раскладку в Android**; Alt+K открывает её настройки. Ctrl+V вставляет текст с ПК. Общий буфер передаёт только **текст**, без файлов и изображений.

## Быстрые команды ADB

Кнопка терминала открывает библиотеку. Укажите название и команду, затем сохраните. Например:

```text
adb shell getprop ro.product.model
```

Префикс `adb` / `adb.exe` необязателен. Телефон выбирается приложением; добавлять перед командой `-s`, `-d`, `-e` не нужно. Поиск работает по названию и тексту. Для кнопки на панели включите «Закрепить на панели быстрого доступа» и сохраните. Полное название и команда видны при наведении; при большом количестве закреплений область прокручивается колёсиком.

Результат и код завершения видны в окне команд. Запуск с панели не открывает редактор; последний результат можно посмотреть в нём позже. Телефон фиксируется на старте команды, остальные кнопки управления остаются доступны. В редакторе есть остановка; лимит выполнения — 60 секунд. Остановка клиента ADB может оставить процесс на Android работающим. Это запуск текстовых команд, а не интерактивный терминал.

Аргументы передаются напрямую в ADB, без cmd.exe или PowerShell. Кавычки после `shell` сохраняются для оболочки Android. Пути Windows с пробелами заключайте в двойные кавычки.

## Язык и локальные файлы

В «⋯ Настройки → Язык интерфейса» доступны «Системный / Русский / English». Системный режим использует русский для `ru-*`, английский — для остальных языков Windows. Переключение применяется сразу без перезапуска трансляции. Названия команд, их текст и вывод устройства не переводятся.

| Данные | Расположение |
| --- | --- |
| Настройки и команды | `%LOCALAPPDATA%\AndroidDesk\settings.json`, `commands.json` |
| Диагностика | `%LOCALAPPDATA%\AndroidDesk\app.log` |
| Видеозаписи | Системная папка «Видео» → `AndroidDesk` |
| PNG-скриншоты | Системная папка «Изображения» → `AndroidDesk` |

Журнал может содержать идентификаторы устройств. Тексты буфера и результаты команд автоматически в него не записываются. Личные данные, записи и результаты сборки исключены из Git.

## Ограничения

Готовое SDL-окно scrcpy встраивается через Win32 `SetParent`; собственного движка трансляции нет. Результат зависит от SDL, видеодрайверов и DPI. Если встраивание на другом ПК не работает, включите «Отдельное окно scrcpy» в настройках.

USB обычно даёт меньшую задержку; Wi-Fi зависит от сети. Android и приложения могут ограничивать захват звука и защищённого изображения. Некоторым телефонам требуется дополнительное разрешение производителя для управления.

## Разработка и проверки

```powershell
.\build.ps1
dotnet run --project .\AndroidDesk.Smoke -- --language
dotnet run --project .\AndroidDesk.Smoke -- --wifi-validation
```

Проверки с настоящим телефоном, запускайте по отдельности:

```powershell
dotnet run --project .\AndroidDesk.Smoke -- DEVICE_SERIAL
dotnet run --project .\AndroidDesk.Smoke -- DEVICE_SERIAL --clipboard
dotnet run --project .\AndroidDesk.Smoke -- --commands DEVICE_SERIAL
dotnet run --project .\AndroidDesk.Smoke -- --wifi IP:PORT
```

Первая создаёт короткую MP4/AAC-запись. Проверка буфера восстанавливает исходный текст. Проверка команд использует чтение данных и короткий sleep. Для Wi-Fi нужен доступный адрес уже сопряжённого телефона. Подробнее: [CONTRIBUTING.md](CONTRIBUTING.md) и [история проверок](VERIFICATION.md).
